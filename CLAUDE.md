# Hive Frontline — project rules

Read this before any task in this repo. `CARBON_RULES.md` beside it is the binding
design spec; this file records how that spec maps onto an architecture it was not
written for, and the handful of facts that are expensive to rediscover.

Last checked against the tree at **v145**. If the version in `_build.sh` is far ahead of
that, assume the specifics below drifted and verify before trusting them.

## The five things most likely to cost you an hour

1. **Never edit `template.html` by hand.** It is generated by the patch chain. A hand
   edit is silently lost on the next `./_build.sh`.
2. **The patch chain is not idempotent.** Each `_*.py` asserts its anchor exists exactly
   N times and fails loudly otherwise. Running one twice, or out of order, is a build
   failure — which is the design. `./_build.sh` is the only supported way to rebuild.
3. **Rebuild the test fixture after every build.** Every JS suite loads
   `/tmp/report_test.html`. If it is older than `template.html` the suites test the
   previous build and pass. `../_test.sh` rebuilds it for you; doing it by hand means
   `FX_TPL=frontline-live-report/template.html FX_REPS=400 python3 _period_fixture.py`.
4. **`pcpm.py` and `towns.py` are shared byte-identical with Channel Health**
   (`channel-health-portal/pipeline/scripts/`). `_pcpm_test.py` fails if they drift.
   Change one, copy it to the other, in the same commit.
5. **There are two repos with similar names.** This one —
   `outputs/frontline-live-report`, 1,176-line `etl.py`, has `__DATA_MARKER__` — is what
   Render deploys as `frontline-report.onrender.com`. `hive-analytics/` is a different,
   older tree; its `etl.py` is 477 lines. Pushing to the wrong one does nothing visible
   and wastes a deploy cycle.

## What this codebase actually is

One self-contained HTML file. `template.html` (~785 KB) holds every CSS rule and every
line of JavaScript inline; `etl.py` renders it once into `report.html`; `app.py` serves
that with a toolbar merged in. No `templates/`, no Jinja, no `static/`, no bundler.

The Carbon handoff assumes Flask with template inheritance. Its four consistency
mechanisms translate as follows.

| Handoff says | Here it is |
| --- | --- |
| One token file, no local literals | `carbon-tokens.css` is inlined verbatim at the top of `template.html`. Below the `END OF TOKENS` marker there is not one colour literal, in CSS or JS, outside a short named-exception list. `_carbon_test.js` and `_audit.py` both fail the build otherwise. |
| One macro per pattern | True, in JS. `kpi()`, `th()`, `chart()`, `pl()`, `ddUpgrade()`, `ttShow()` are the macro layer. Add a pattern as a function, never as inline markup in a view. |
| Rules file at the repo root | This file plus `CARBON_RULES.md`. |
| Screen by screen with a review gate | The patch chain is that gate: one reviewable script per step, each with its own suite. |

## The alias layer

`template.html` refers to `--bg`, `--surface`, `--ink`, `--line`, `--accent` in hundreds
of rules. `_carbon.py` redefines those names in terms of `var(--cds-*)`. **Change colour
by editing the alias block, never by editing a rule.**

Since v139 there are three hover aliases and they are not interchangeable:
`--hov-01` on grey layers, `--hov-02` on white, `--hov-page` on the page itself. Pick by
the surface the element sits on, never by what the element is. `--hover` survives as an
alias of `--hov-01` for anything that escaped the sweep; `_interact_test.js` fails the
build if a new rule uses it.

The dark theme carries no palette of its own: every alias points at a Carbon token, and
Carbon's g100 block answers to both `[data-carbon-theme="g100"]` and the app's existing
`[data-theme=dark]`.

## The build

`./_build.sh` in the outputs folder rebuilds `template.html` from
`_std_template_v12.html` through ~70 patch scripts, v13 to v145. It then runs five
gates, all of which must pass:

- `node --check` on the concatenated inline script — v71 shipped a broken split
  declaration and took the whole report down while every other gate passed.
- The escape guard: no people field may be interpolated into markup without `esc()`.
- `_testlint.py --strict` — inside a template literal a backslash is a template escape,
  so `/\s+/` silently becomes `/s+/`. Three suites shipped with that.
- `_uiaudit.py --strict` — zero UNSTYLED classes.
- `_audit.py` — the 19-item Carbon conformance score. Currently 18/19 with one item
  genuinely unverifiable by machine; it must not fall.

`app.py` and `etl.py` patches (`_minimize.py`, `_roster.py`, `_pcpm_etl.py`) are applied
**in place**, are **not** re-run by `_build.sh`, and are **not** idempotent. Backups are
in `/tmp`. Check before running one.

## Tests

```
../_test.sh pcpm        # only what you touched — seconds, use this while working
../_test.sh -q          # all but the four heaviest, ~1m50
../_test.sh             # all 48, ~3m30 — needs two calls at the host's limit
```

48 suites, 41 JavaScript and 7 Python. Run the full set before pushing. The runner
rebuilds the fixture, orders longest-first, and prints the failing suite's output.

## Two runtime dependencies, both optional by design

- **Channel Health** — the productivity matrix fetches sales over its read-only API at
  ETL time (`CHR_API_TOKEN`, header `X-API-Token`). If it is unreachable the matrix is
  emitted as unavailable with the reason attached and a cached response is reused; every
  other screen is untouched.
- **d3 and topojson** — pinned on unpkg with integrity hashes, loaded `defer`, used only
  by the matrix map. If they fail to load the map prints one line and every figure on the
  screen is unaffected. That is why `pmMapInit()` is lazy and guarded by `typeof d3`: a
  `d3.select()` at script top level would break every screen and all 41 JS suites.

## The drill panel hosts sections, it does not copy them

`drillOpen(key)` **moves** `#sec_<key>` into the panel and moves it back on close. Never
clone a section: this document looks elements up by id constantly, so a copy gives you
two `#pb` tables and handlers wired to whichever one lost.

The three screens that left the sidebar keep their nav buttons under `.navhidden`. That
is what makes `go('prod')`, old bookmarks, share links and `restoreState()` still work.
Do not delete them.

## What not to change

Per `CARBON_RULES.md`: no route paths, no query parameters, no column order. And here:

- Never mutate `BASE`.
- Never widen `/status` to carry employee codes — **it has no authentication**.
- Never let an export read the data model instead of the rendered DOM.
- Only code, name, HQ, designation and exit date may come out of the HR files. No phone
  numbers, addresses, dates of birth or personal emails.
- `hr.json` and `bb_org.json` hold staff mobile numbers and employee names and are
  committed. **Do not attach this repo to a design tool** — use
  `hive-analytics/frontline-design-handoff/`, which carries synthetic data on purpose.

## Vocabulary on the productivity matrix

The client's words, and the ETL's internal ones, are different on purpose. `pmBandOf()`
is the single place they meet.

| Reader sees | ETL says |
| --- | --- |
| Needs help / Improving / Close to target / On target | RED / BUILD / STRETCH / PERFORM ZONE |
| approved positions | sanctioned posts |
| people in place | filled |
| matched / not matched to a headquarters | attributed / unattributed |
| Nobody in place yet | no one posted |
| Figure not reliable | not scored |

`_pcpm_test.js` fails if any of the right-hand column reaches the screen.

## Business rules that look like bugs

- **PCPM is sales ÷ people ÷ months.** The original spec said `× months`; that is an
  inverted typo which reports the square of the period and turns the whole grid green.
- **A month counts once its data reaches the 26th.** Channel Health's rule, repeated in
  `pcpm.py` rather than imported so the two can be shown to agree.
- **Measured on `goods`, pre-tax, GST excluded** — not `sales`, which is GST-inclusive.
- **Each division is measured only on its own products.** A sale in a town where its
  division has nobody posted is reported separately, never credited to whoever else is
  there. `check()` fails the build if a row carries another division's billing.
- **The headcount registers are disjoint**: `hq: r.hhq || r.hq` files a person under
  their HR headquarters, and the HR-only block excludes anyone already in the rep
  roster. Summing them is correct; it looks like double-counting and is not.
